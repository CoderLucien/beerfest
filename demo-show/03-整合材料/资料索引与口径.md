## 4. 统一事实口径

| 类型 | 例子 | 舞台表达 |
|---|---|---|
| 公开事实 | 2025 年会场客流和活动周期 | 明确来源和年份 |
| 演示假设 | 排队 22 分钟、库存 420、预算 6000 元 | 页面标注“模拟数据” |
| 现场实测 | Brief 到 V1、V2 的实际时间和测试结果 | 现场填写，不提前写入 |
| 规划目标 | 未来 PoC 的开发或经营指标 | 使用“目标”“待验证” |

## 5. Demo 中不应使用的表达

- “Loop 固定可以在十分钟交付完整系统”；
- “Agent Team 一定比传统团队快十倍”；
- “模拟活动带来了真实的 GMV 或利润提升”；
- “Agent Team 会被普通频道消息自动唤醒”；
- “创建很多 Agent 就代表并行效率更高”；
- “应用生成以后就完成了软件交付”；
- “完整四产品方案已经由某一个公开客户全部落地”。

## 6. 当前专项结论

主线标题：

> **从一个 Agent 写代码，到一个 Agent Team 持续交付业务。**

Loop 提效证据：

1. Leader 把模糊需求变成统一范围和验收标准；
2. Developer 与 Reviewer 在依赖允许的位置并行；
3. Artifact、Checkpoint 和任务上下文减少交接损失；
4. 独立 Review 在发布前发现问题；
5. V2 复用 V1 的工作现场、代码和测试资产。

业务价值证据：

1. 从客流异常生成结构化促销方案；
2. 活动必须经过资格、预算、库存和人工审批；
3. 运行达到阈值可以自动暂停；
4. 通过实验组和对照组评估增量，不只看领券量；
5. 经营反馈继续进入产品和规则迭代。
