## 4. 关键架构决策

### 4.1 智能问数：Plan B 混合方案（结构化查询模板 + LLM 路由）

- **决策**：LLM 不直接生成 SQL，而是从 8 个预定义查询模板中选型 + 填参，SQL 由开发者编写审核
- **收益**：数据类问题 100% 确定性（与看板同口径）、零注入风险、每次查询仅 1 次 LLM 调用
- **模板**：promotion_stats / revenue_summary / coupon_breakdown / top_orders / user_stats / revenue_by_type / anomaly_check / comparison
- **兜底**：未匹配 → 回退通用 Ops Chat；参数缺失 → 澄清追问，不编造

### 4.2 诚实数据边界（防虚构，L3 门禁 100% 不妥协）

- 无区域/门店/时间趋势维度的提问 → 明确声明「当前无该维度数据」+ 最近似参考
- 分析类回答强制标注「推测/分析」，与精确数据视觉区分（橙色标注卡片）
- 空数据兜底：「未找到「XX」相关券种数据」，杜绝模板占位符泄漏

### 4.3 LLM JSON 稳定性：sanitizeLLMJSON 三层防御

- 提取 ```json 代码块 → 容错解析 → 字段级兜底，DeepSeek 偶发格式波动不影响服务

### 4.4 小游戏帧率无关化

- 位移按 `speed * dt * 60` 缩放，修复 120Hz 高刷屏双倍速问题；三阶段速度/生成间隔参数化

| 项 | 说明 | 建议 |
|----|------|------|

## 8. 经验沉淀

1. **验收门禁量化先行**：L1/L2/L3 + 延迟 + UI + 回归 7 道门禁，逐条阈值，验收不再靠感觉
2. **确定性优先于灵活性**：数据类问题走模板计算而非 LLM 生成，准确、可验收、口径统一
3. **诚实边界是产品价值而非缺陷**：明确说「没有这个数据」+ 最近似参考，比编造答案更受运营信任
4. **三层验证方法可复用**：静态审查（diff/参数核对）→ 自动化脚本（模拟/loadtest）→ 浏览器实测，成本低、拦截率高
5. **修复必须闭环复验**：RD 修缺陷 → QA diff 精确核对「仅改预期行」→ 部署后线上生效复验，三次确认杜绝漂移
6. **热部署与回滚**：静态页 inode 覆盖热部署 + served==本地全等比对，前端迭代分钟级生效
